Hi everyone!

We have released Expert v0.2. This has been a big effort by several people and marks an important milestone for Expert.

This release has been focused on these aspects: performance, merging the NextLS indexing architecture into Expert, and porting the remaining ElixirLS features.

Before we dice into the release details, let's thank the project sponsors and contributors.

## What's new

We have reworked Expert's indexer(the system that analyzes your project to find definitions and references) to be faster and more complete. NextLS used SQLite as its _backend_, while prior to this release Expert used a combination of ETS and a `:disk_log` based WAL, which caused issues if you had multiple Expert instances running against the same project, and was generally hard to maintain; moving to SQLite fixed both issues.

Another important piece of NextLS was its usage of Compiler Tracers. Expert indexes your project by reading your source code files, this is nice because we can see all the code you wrote and be accurate about the things we index, but has the downside that any function or module definition created via macros/metaprogramming was invisible to it. Compiler Tracers on the other hand provide you with the BEAM metadata the compiler sees, which includes functions and modules created via macros, but do not include _anything_ for .exs files because those don't run through the compiler. Expert is technically able to index your code while or before it gets compiled, so we implemented a middle ground: we now read your compiled .beam files to index any generated code that we can't find just by analyzing the source code.

Aside from that, we've also made several performance improvements, which were backported to the 0.1 releases due to their impact. Users have reported the indexer running about **5x faster** and the ElixirSense completions cache has received a similar speedup, drastically reducing the overall startup times for Expert. Code formatting has also been improved, preventing the Expert formatter to freeze on large codebases, and making it easier for clients to apply the changes efficiently.

On top of that, we've also ported the remaining NextLS features that were missing form Expert:

- Document Outline for files with syntax errors
- Workspace Folders
- "Add missing require" and "Create undefined function" code actions

The frollowing features from ElixirLS were ported into expert:

- Call Hierarchy
- Declarations
- Implementations
- Selection Ranges
- Signature Help

And added entirely new features:

- Hex dependency completions
- Configuration for your elixir+otp toolchain
- Offline support
- Remote shell for debugging

## What's next

Now that we have a stable foundation, we are ready to start implementing new features that were not part of Lexical, NextLS or ElixirLS. You can track our progress by visiting our [milestones](https://github.com/expert-lsp/expert/milestone/3).

This is where we will focus our efforts, however you are welcome to contribute with any feature of change you think would be nice to have in Expert, even if it's not planned in our roadmap!

## How to help

Please try the release candidate and report any bugs you come across! Getting bug reports with proper reproduction cases along with all relevant information like your `.expert/expert.log`, OS, Elixir version, Erlang version, project size, etc is extremely helpful.
